# B16 Live Auto Executor Plan

## Goal

Connect B16's current cross-sectional factor ranking to the Moomoo live strategy sub-ledger without importing any B16 paper account state or paper trading parameters.

## Non-negotiable invariant

Paper B16 and live B16 share only the active factor definition and resulting ranking. Live cash, positions, average cost, target sizing, top-N, gross exposure, stop loss, cooldown, minimum hold, hold band, rebalance timing, order limits and execution state come exclusively from `live_strategy.db` and Moomoo's proven module orders/fills.

## Current proven foundation

- Shared-restricted account reconciliation and owned-quantity invariant.
- Long-only BUY/SELL guards.
- Signed preview, fresh quote, RTH, price-deviation, order/day notional and cash gates.
- Real DRAM BUY fill, fee import, restart and idempotent reconciliation.
- Freeze/cancel watchdog, generation-bound sync proof and five-minute reconciliation.
- Trading master enabled; automatic trading disabled.

## Task 1: Pure read-only B16 signal adapter

Create `core/live_signal_adapter.py`.

- Open `/home/gexin/quant-trading/data/trading.db` with SQLite `mode=ro`.
- Read the latest complete `factor_group='gp_B16'` cross-section.
- Read active B16 factor names from `mined_alphas_per_account.json` without importing or constructing `QuantSystem`.
- Reproduce `GPSignalGenerator` percentile-rank mean exactly.
- Return signal batch ID, source date, factor-set hash, ordered BUY candidates and SELL tail.
- Fail closed on missing factors, partial latest cross-section, future/stale source date or non-finite values.
- Prove output matches the existing B16 prepared ranking fixture.

## Task 2: Independent live portfolio planner

Create `core/live_auto_planner.py`.

Inputs are only:

- read-only B16 ranking batch;
- live `strategy_config`;
- live owned positions and average costs;
- live allocated cash/equity;
- current Moomoo quotes;
- module-owned pending orders/intents.

Rules:

- SELL live owned positions first when stop-lossed or outside the live hold band, subject to live minimum-hold rules.
- BUY from ordered B16 candidates until live `top_n`, `position_target_pct` and `gross_target_pct` are satisfied.
- Never read paper B16 cash, positions, trades, costs, cooldown or rebalance state.
- Never sell more than live owned minus pending strategy SELL quantity.
- Use whole US shares, long-only, RTH DAY limit orders.
- Emit a deterministic plan; no Broker mutation.

## Task 3: Durable at-most-once intents

Add a live-strategy intent table and methods.

- Deterministic intent key binds strategy, live config version, signal batch, purpose, symbol, side and target quantity.
- States: `PLANNED`, `RESERVED`, `DISPATCHING`, `ACKED`, `PARTIAL`, `FILLED`, `CANCELLED`, `FAILED`, `UNKNOWN`.
- Same key/same payload is idempotent; same key/different payload freezes.
- Persist before Broker mutation.
- `DISPATCHING`/`UNKNOWN` is never automatically resent; recover only from Broker order/deal/remark reconciliation.
- BUY notional and SELL quantity reservation must be transactionally accounted before dispatch and released/replaced by proven Broker pending quantity.

## Task 4: Single-cycle auto executor

Create `core/live_auto_executor.py` and `scripts/live_auto_cycle.py`.

Preflight requires:

- `MOOMOO_TRADING_ENABLED=true`;
- `MOOMOO_AUTO_TRADING_ENABLED=true`;
- lifecycle `ACTIVE`;
- exact current generation sync proof and sync within seven minutes;
- US RTH from both New York clock and Moomoo market state;
- healthy complete order/deal history;
- no unresolved `DISPATCHING`/`UNKNOWN` intent;
- signal and factor-set freshness.

Execution:

- Global file lock shared with reconciliation/order dispatch.
- Reconcile before planning.
- One deterministic order dispatch at a time; SELL priority.
- Reuse signed `preview_order` and final re-preview in `place_order`.
- Trade token is read only from the `0600` environment file; never argv/log/intent/event.
- Broker unknown outcome freezes and does not retry.
- Reconcile immediately after ACK.

## Task 5: Scheduler and recovery

Create a secret-free wrapper and schedule only during US RTH. The script self-gates on exchange state, so cron UTC/DST drift cannot trade outside RTH.

- Shadow mode is the default while `AUTO=false` and writes a sanitized plan only.
- Startup scans unresolved intents and reconciles them before any new plan.
- Frozen state cancels proven module orders and emits no new intent.
- Existing paper `run_cycle` remains separate and cannot invoke live execution.

## Verification gates

1. Pure adapter output equals current B16 ranking generated by the legacy path.
2. Tests prove paper B16 account mutations do not change live plans.
3. Tests prove live config changes do change live plans and invalidate stale intents.
4. Duplicate cron, restart and timeout tests prove at-most-once dispatch.
5. UNKNOWN outcome never retries.
6. Partial fill and fee reconciliation remains idempotent.
7. SELL cannot exceed live owned when personal holdings share the symbol.
8. RTH/market-state/source-age/quote-age failures are fail-closed.
9. Token absent from argv, logs, DB and events.
10. Full suite, compile checks, shell checks, SQLite backup/restore and production shadow run pass before requesting `AUTO=true` authorization.
